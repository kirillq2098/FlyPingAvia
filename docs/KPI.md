## Принцип

Считаем только то, для чего есть (или легко добавить) источник данных.  
Цифры «на глаз» и целевые 100k без воронки сюда не пишем — только вопросы в TODO.

## Что можно измерить уже сейчас

| Метрика | Как получить сегодня | Зачем |
|---------|----------------------|--------|
| Пользователи в БД | `COUNT(*)` из `users` | Размер базы |
| Активные подписки | `COUNT(*)` из `watches WHERE is_active` | Engagement продукта |
| Подписки на пользователя | watches / users | Насколько «зацепило» |
| Доля RT vs OW | watches с/без `return_date` | Какой сценарий доминирует |
| Сервис жив | `GET /api/health` (local + public URL) | Надёжность |
| Demo vs live prices | `demo_prices` в `/api/health` | Не врут ли цены |
| Live search status | `live_search` = disabled/denied/configured | Готовность pax |
| Ошибки туннеля/бота | `/tmp/flypingavia/*.log` при supervise | Ops |

В коде **нет** готовых дашбордов и экспорта этих KPI.

## Чего нельзя честно считать из продукта сегодня

| Метрика | Почему нельзя |
|---------|----------------|
| CTR по партнёрской ссылке | Нет своего трекинга кликов |
| Бронирования / CPA revenue | Только вне репо — кабинет Travelpayouts (если настроен) |
| Retention D1/D7 | Нет событийной аналитики (только `created_at`) |
| Funnel /start → watch → alert → click | Alert есть, click/покупка не логируются |
| CAC / LTV | Нет маркетинговых затрат и выручки в системе |
| Конверсия в оплату | Оплаты нет |

## North Star — кандидаты

Рабочий выбор стратегии: **Alerted Watchers (30d)** — см. [FLYPING_STRATEGY](FLYPING_STRATEGY.md). Ниже — исходные кандидаты для сверки.

1. Число пользователей с ≥1 активной подпиской  
2. Число алертов, после которых был переход к билетам  
3. Партнёрская выручка в месяц  
4. **Alerted Watchers (30d)** — users с активной подпиской и ≥1 валидным алертом за 30 дней *(выбран в стратегии)*
