# Competitive Analysis — рынок поиска и отслеживания авиабилетов

Связанные документы: [Vision](PRODUCT_VISION.md) · [Roadmap](MASTER_ROADMAP.md) · [Monetization](MONETIZATION.md) · [Marketing](MARKETING.md) · [KPI](KPI.md)

**Дата обзора:** 2026-07  
**Метод:** публичные help-центры, продуктовые страницы, обзоры бизнес-моделей, каталоги Telegram-ботов.  
**Ограничение:** внутренние SLA алертов и точные комиссии партнёров у конкурентов закрыты — где данных нет, помечено как *не публикуется / косвенно*.

## Контекст рынка

Рынок делится на три слоя:

1. **Metasearch** (Aviasales, Skyscanner, KAYAK, Momondo, Google Flights) — сравнение цен, редирект на OTA/авиакомпанию, монетизация CPC/CPA/ads.
2. **OTA / booking** (Kiwi.com, Trip.com, Hopper) — продажа билета «у себя», сервисные сборы, гарантии, ancillaries.
3. **Watch / alert layer** — подмножество функций внутри гигантов (Price Alerts, Track prices) плюс нишевые боты и deal-сервисы.

**FlyPingAvia** сегодня — слой 3 внутри Telegram (бот + Mini App), с CPA-редиректом на Aviasales. Это не конкуренция «кто больше авиакомпаний», а конкуренция за **привычку следить и вовремя купить**.

## 1. Aviasales (Авиасейлс)

| Поле | Содержание |
|------|------------|
| **Идея** | Метапоиск дешёвых авиабилетов (и смежных travel-услуг) для русскоязычного рынка; «сравнить → купить у агентства». |
| **Аудитория** | Самостоятельные туристы РФ/СНГ и русскоязычная диаспора; сильный мобильный трафик. |
| **Главные функции** | Поиск OW/RT, фильтры, календарь цен, карта низких цен, «горячие билеты», избранное, отели/смежное. |
| **Уведомления** | В приложении/сайте: избранное (сердечко) → push при изменении цены. Отдельный Telegram-бот **@AviasalesCheapTicketsBot** («напишу, когда цены упадут») — подписка на направление/даты, управление подписками, автоистечение. |
| **Поиск** | Агрегация предложений авиакомпаний и агентств; пользователь уходит оформлять к продавцу. |
| **Мобильное приложение** | Да (iOS/Android); существенная доля бронирований с мобильных. |
| **Telegram-бот** | Да, официальный бот низких цен + контент-канал @aviasales. |
| **Монетизация** | Комиссия с продаж (CPA), не чистый CPC; партнёрская сеть **Travelpayouts** (ссылки, виджеты, white label, API). |
| **Сильные стороны** | Локализация и доверие в RU; зрелый продукт; свой Telegram-бот; сильная партнёрка для издателей. |
| **Слабые стороны** | Продукт широкий (поиск+контент+отели) — слой «только watchdog с жёстким порогом» не выделен как отдельный UX; алерт «цена изменилась» ≠ контракт «цена ≤ мой бюджет» (в публичном описании бота акцент на падении цены, не на пользовательском пороге как в FlyPing). |
| **Что можно улучшить у них** | Более явный user-defined threshold и антиспам; узкий «режим ожидания» без возврата в полный поиск. |

**Вывод для FlyPing:** прямой конкурент в RU Telegram. Отстройка — не «лучше Aviasales», а **уже / понятнее контракт порога + меньше шума**, с монетизацией через их же Travelpayouts.

## 2. Skyscanner

| Поле | Содержание |
|------|------------|
| **Идея** | Глобальный travel metasearch: flights + hotels + cars; «everywhere» и гибкие даты. |
| **Аудитория** | Массовый международный traveler; сильный SEO и бренд сравнения цен. |
| **Главные функции** | Everywhere, Whole Month, Price Alerts, Drops, фильтры, мультипродукт. |
| **Уведомления** | Price Alerts: email и push в приложении при движении цены по сохранённому поиску. |
| **Поиск** | Скан сотен провайдеров → редирект на airline/OTA; Skyscanner сам билет не продаёт (классический metasearch). |
| **Мобильное приложение** | Да. |
| **Telegram-бот** | Официального продукта-бота мониторинга (как у Aviasales) **не подтверждено**; есть Telegram-канал/маркетинг и сторонние боты с похожими именами — не считать официальным продуктом. |
| **Монетизация** | Referral / commission и CPC от партнёров, sponsored listings, ads, data; пользователю бесплатно. Входит в экосистему **Trip.com Group**. |
| **Сильные стороны** | Глубина поиска, flexible/everywhere UX, глобальный охват, сильный app retention через алерты. |
| **Слабые стороны** | Нет нативного «жить в Telegram» UX; продукт тяжёлый для сценария «просто сторожи одну поездку»; алерты завязаны на экосистему email/app. |
| **Что можно улучшить** | Лёгкий messaging-канал с порогом и одной кнопкой «к билетам». |

## 3. Google Flights

| Поле | Содержание |
|------|------------|
| **Идея** | Бесплатный поиск и аналитика цен Google; доверие к данным и скорость UI. |
| **Аудитория** | Все, кто уже в Google; особенно пользователи с конкретным маршрутом и датами. |
| **Главные функции** | Поиск, date grid, price graph, Explore, Track prices (маршрут / конкретный рейс / Any dates), insights «цена скоро вырастет». |
| **Уведомления** | Email (и mobile notifications на Android/iOS при использовании приложения Google) при **значительном** изменении цены; для Any dates — при сильном падении минимума за месяц или регулярный дайджест лучших цен. Insights о вероятном росте и истечении тарифа. |
| **Поиск** | Собственный индекс/агрегация Google Travel; редирект на продавцов. |
| **Мобильное приложение** | Отдельного «Google Flights app» как у Hopper нет; мобильный web + уведомления через экосистему Google / Travel. |
| **Telegram-бот** | Нет. |
| **Монетизация** | Для пользователя бесплатно; Google монетизирует travel через рекламу/экосистему поиска (прямая CPA с билета — не публичная «главная» модель продукта Flights). |
| **Сильные стороны** | Качество UI и данных; «Any dates»; прогнозные insights; нулевой friction входа (Google Account). |
| **Слабые стороны** | Алерты **не мгновенные** (публичная критика: можно пропустить flash/mistake fare); критерий «significantly» непрозрачен для пользователя; слабая доставка в мессенджеры; нет жёсткого «алерт только если ≤ N ₽». Автоотключение трекинга близко к вылету (по сторонним гайдам — порядка 72 часов; сверять с актуальным help). |
| **Что можно улучшить** | Порог пользователя, скорость доставки, канал Telegram. |

**Вывод для FlyPing:** Google выигрывает поиск; проигрывает **контракт порога + мгновенный мессенджер**. Это главный white space относительно Google Flights.

## 4. Hopper

| Поле | Содержание |
|------|------------|
| **Идея** | Mobile-first travel + **fintech**: предсказать цену и продать защиту от неопределённости (Price Freeze и др.). |
| **Аудитория** | Gen Z / millennials, app-native, в основном US/международные рынки Hopper. |
| **Главные функции** | Прогноз Wait/Buy Now, Price Watch, Price Freeze, cancellation/disruption products, hotels/cars, Carrot Cash. |
| **Уведомления** | In-app / push: слежение за ценой и сигналы «покупать / ждать». |
| **Поиск** | Marketplace/OTA-подход с партнёрским инвентарём + ML-прогнозы. |
| **Мобильное приложение** | Да (ядро продукта). |
| **Telegram-бот** | Нет (продукт app-centric). |
| **Монетизация** | Комиссии с бронирований + **высокая доля ancillary/fintech** (Price Freeze и защиты; публично озвучивалось ~70% air revenue с ancillaries в прошлых интервью). B2B: Hopper Technology Solutions. |
| **Сильные стороны** | Чёткий ответ на тревогу «покупать или ждать»; монетизация не только кликом. |
| **Слабые стороны** | Сложность/доверие к Freeze (регуляторные претензии в прошлом); не про RU/Telegram; тяжёлый стек для копирования маленькой командой. |
| **Что можно улучшить** | Прозрачность условий Freeze; лёгкий watchdog без покупки билета у себя. |

**Вывод для FlyPing:** не копировать Freeze на старте (High сложность + капитал на хедж). Взять идею **явной рекомендации относительно рынка** (у FlyPing уже есть вилка дёшево/обычно/дорого) и усиливать её в алертах.

## Сводные слабости рынка (паттерны)

1. **Алерт ≠ контракт.** У большинства «цена изменилась / упала / ±10%», а не «достигнут мой потолок в рублях».  
2. **Доставка.** Email и app push проигрывают привычке «живу в Telegram» (особенно RU). Кроме Aviasales, крупные игроки Telegram-watchdog почти не освоили.  
3. **Шум.** Daily digests и «significant change» без тихих часов → усталость и отключение алертов.  
4. **Тяжёлый продукт.** Суперapps и metasearch заставляют пользователя вернуться в большой UI, чтобы «просто сторожить поездку».  
5. **Прозрачность решения.** Hopper/KAYAK/Google дают buy/wait или graph, но в самом сообщении алерта редко видно «это дёшево относительно рынка *прямо сейчас*».  
6. **Атрибуция для создателей.** Гиганты зарабатыют сами; нишевому боту нужна ясная CPA + sub-marker — у FlyPing база есть, канала атрибуции в продукте ещё нет.

## Opportunities for FlyPing

Ниже — только идеи, опирающиеся на слабости выше и на уже существующий код FlyPing. Не «построить свой Skyscanner».

### O1. Жёсткий контракт порога в каждом алерте

| | |
|--|--|
| **Проблема** | У Google/KAYAK/многих алертов критерий срабатывания размыт («значимо», ±%). Пользователь не понимает, зачем пришло уведомление. |
| **Решение** | В алерте всегда явно: «цена X ≤ ваш порог Y», дельта до порога, кнопка к билетам. (База уже есть: `max_price`, formatters.) |
| **Эффект** | Выше доверие и CTR по партнёрке; меньше отписок. |
| **Сложность** | Low |
| **Влияние на рост** | Medium |

### O2. Антиспам: алерт только при новом минимуме / cooldown

| | |
|--|--|
| **Проблема** | Повторные уведомления на ту же цену раздражают (KAYAK daily digests, общий market pain). В FlyPing `last_alert_price` пишется, но не глушит повторы. |
| **Решение** | Алертить если цена ≤ порога **и** (нет прошлого алерта **или** цена заметно ниже `last_alert_price` **или** прошёл cooldown). Опционально «тихие часы». |
| **Эффект** | Retention подписок; выше воспринимаемое качество. |
| **Сложность** | Low–Medium |
| **Влияние на рост** | High (удержание) |

### O3. «Относительно рынка» внутри алерта, не только при создании

| | |
|--|--|
| **Проблема** | Hopper/KAYAK/Google учат buy/wait в UI поиска; в push часто только «цена упала». Пользователь не знает, хороша ли цена. |
| **Решение** | В алерте кратко повторять вилку: 🟢/🟡/🔴 + «обычно ~median». (Вилка уже считается в checker/prices.) |
| **Эффект** | Сильнее решение «открыть билеты сейчас»; меньше ложных ожиданий. |
| **Сложность** | Low |
| **Влияние на рост** | Medium |

### O4. Telegram-first watchdog для RU без установки ещё одного travel-app

| | |
|--|--|
| **Проблема** | Trip.com/Skyscanner/Momondo требуют app/web; только Aviasales системно в Telegram. Пользователи не хотят 5 travel-приложений ради одной поездки. |
| **Решение** | Позиционирование: «не ищем 1000 рейсов — сторожим вашу поездку в чате». Усилить onboarding /start → 1 подписка за &lt; минуту (уже близко к FSM + Mini App). |
| **Эффект** | Низкий CAC в RU Telegram; вирусность через forward карточек. |
| **Сложность** | Low (копирайт/UX) … Medium (шаринг) |
| **Влияние на рост** | High |

### O5. Шаринг карточки «я жду цену ≤ N» (без полноценного соц. продукта)

| | |
|--|--|
| **Проблема** | У гигантов слабый органический шаринг алертов; маркетинг платный. |
| **Решение** | Кнопка «Поделиться» в Telegram: маршрут + порог + «бот напишет, когда станет дешевле» + deep-link `?start=`. |
| **Эффект** | Органический рост; измеримый канал (если разобрать payload). |
| **Сложность** | Medium |
| **Влияние на рост** | High |

### O6. Sub-marker / deep-link для блогеров

| | |
|--|--|
| **Проблема** | Travel-гиганты не дают маленькому каналу прозрачную атрибуцию; блогеру нужен свой хвост CPA. |
| **Решение** | `?start=blogger_x` → сохранить источник на user; разные `marker`/sub_id в affiliate URL. (Сейчас один `AFFILIATE_MARKER`.) |
| **Эффект** | Канал роста через креаторов; данные для [MARKETING](MARKETING.md)/[KPI](KPI.md). |
| **Сложность** | Medium |
| **Влияние на рост** | High |

### O7. Не обещать «мгновенность Google», обещать «проверили только что»

| | |
|--|--|
| **Проблема** | Google критикуют за задержку алертов; пользователи не доверяют «когда угодно». |
| **Решение** | В карточке/алерте timestamp `last_checked_at` + кнопка «Проверить сейчас» (уже есть `/check` и wcheck). Не позиционировать как mistake-fare sniper. |
| **Эффект** | Честное ожидание; меньше разочарований vs flash-sale сервисов. |
| **Сложность** | Low |
| **Влияние на рост** | Low–Medium (доверие) |

### O8. Бюджетный онбординг как у Trip.com — но в чате

| | |
|--|--|
| **Проблема** | Люди не знают, какой порог ставить; Trip.com решает слайдером + red/yellow/green. |
| **Решение** | Уже есть пресеты дёшево/обычно; усилить: «если поставите дешевле P25 — алертов почти не будет» (явный trade-off). |
| **Эффект** | Больше успешных алертов → больше кликов CPA. |
| **Сложность** | Low |
| **Влияние на рост** | Medium |

### O9. Не строить native iOS/Android на старте

| | |
|--|--|
| **Проблема** | Все крупные конкуренты тянут в app store; для MVP это High cost без преимущества в RU, где Telegram уже «домашний экран». |
| **Решение** | Сознательно оставаться bot + Mini App до доказанной юнит-экономики ([MONETIZATION](MONETIZATION.md)). |
| **Эффект** | Фокус ресурсов на O1–O6; быстрее итерации. |
| **Сложность** | Low (решение) |
| **Влияние на рост** | Medium (через скорость) |

### O10. Не копировать Price Freeze / virtual interlining

| | |
|--|--|
| **Проблема** | Слабости Kiwi (self-transfer) и Hopper (сложный fintech) манят «уникальностью», но требуют капитала, поддержки и юридического контура. |
| **Решение** | Явный non-goal до масштаба: не продаём билет сами, не хеджируем тариф. |
| **Эффект** | Защита фокуса; меньше операционного риска. |
| **Сложность** | Low |
| **Влияние на рост** | Medium (через фокус) |
