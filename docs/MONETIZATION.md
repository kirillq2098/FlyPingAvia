## 1. Уже реализовано: Affiliate / CPA

**Как работает**

- При подтверждении подписки, в карточках и в алертах строится URL  
  `https://www.aviasales.ru/search?...&marker=<AFFILIATE_MARKER>&...`
- Реализация: `flypingavia/services/prices.py` → `build_affiliate_url`
- Запросы к Data API идут с `show_to_affiliates=true`
- Маркер по умолчанию в `.env.example`: `AFFILIATE_MARKER=flypingavia`
- Для Flight Search используется `TRAVELPAYOUTS_SEARCH_MARKER` (или fallback на affiliate marker) + host `LIVE_SEARCH_HOST` (default `flypingavia.app`)

**Что это даёт бизнесу**

- Выручка возможна только если пользователь перейдёт по ссылке и совершит покупку, атрибутированную маркеру в кабинете Travelpayouts/Aviasales.

**Чего нет в коде**

- Учёт кликов внутри FlyPingAvia
- Postback / сверка выплат
- Разные marker’ы на каналы (блогер A / блогер B)

## 4. Финансовая модель

В репозитории **нет** таблицы unit-economics, CAC, LTV, прогноза P&L.

Черновик формул (не заполнять выдуманными цифрами):

```text
Выручка ≈ (алерты × CTR в партнёрку × CR в покупку × CPA)
         + (платящие × ARPU)          # когда появится подписка
Расходы ≈ хостинг + API/лимиты партнёра + маркетинг + время команды
```

## 5. Риски монетизации (известные)

| Риск | Почему актуален сейчас |
|------|-------------------------|
| Нет атрибуции внутри продукта | Не видно, какие алерты дают деньги |
| Demo-режим без токена | Нельзя обещать рыночные цены |
| Flight Search access denied | Состав пассажиров и «истинный» RT недоступны |
| Ephemeral tunnel URL | Mini App и кнопка ломаются при смене URL |
| Зависимость от одного партнёра | Aviasales/Travelpayouts = и цены, и деньги |
