# User Journey — FlyPing

Связанные документы: [Vision](PRODUCT_VISION.md) · [Strategy](FLYPING_STRATEGY.md) · [Feature Backlog](FEATURE_BACKLOG.md) · [Competitive Analysis](COMPETITIVE_ANALYSIS.md) · [Marketing](MARKETING.md)

**Назначение:** пошаговый путь пользователя по *текущему* продукту (бот + Mini App, MVP 0.2).  
Улучшения ссылаются на ID из [FEATURE_BACKLOG](FEATURE_BACKLOG.md), где возможно.  
**Гипотезы** помечены явно — каналы привлечения и поведение после покупки на Aviasales в продукте не логируются.

**Happy path (ядро):** нашёл бота → `/start` → создал watch → получил алерт → открыл «Смотреть билеты» → вернулся → второе отслеживание.

## Шаг 0. Пользователь впервые находит FlyPing

| Поле | Содержание |
|------|------------|
| **Цель пользователя** | Понять, «что это» и стоит ли тратить минуту; найти способ следить за ценой без постоянного поиска. |
| **Что видит** | **Факт сегодня:** нет SEO-лендинга и deep-link атрибуции в коде. Типичный вход — ссылка `t.me/<bot>` от знакомого, из чата или от автора. **Гипотеза:** путает с @AviasalesCheapTicketsBot или с самим Aviasales. |
| **Действия** | Тап по ссылке / поиск username в Telegram → экран бота → «Запустить». |
| **Где может запутаться** | Непонятно отличие от Aviasales; нет превью ценности до /start; имя FlyPingAvia vs «FlyPing» в стратегии. |
| **Точки отказа** | Не нажал Start; закрыл бота; выбрал официальный Aviasales bot вместо нас. |
| **Как улучшить** | USP в одной строке в описании бота (BotFather); deep-link `?start=` + блогер-кит ([TG-03](FEATURE_BACKLOG.md), [GR-02](FEATURE_BACKLOG.md)); формулировка watchdog из Strategy в bio. |
| **Приоритет улучшения** | **P1** (нужно к росту 100→1k; для первых 100 достаточно ручной ссылки) |

## Шаг 1. Запускает Telegram-бота

| Поле | Содержание |
|------|------------|
| **Цель пользователя** | Открыть диалог и получить доступ к функциям. |
| **Что видит** | Кнопка «Запустить» / команда `/start`. После старта создаётся запись `users` (`telegram_id`). |
| **Действия** | Нажимает Start или отправляет `/start`. |
| **Где может запутаться** | Ожидает сразу Web App из menu button (мы сознательно не ставим MenuButtonWebApp на tunnel URL — [TG-05](FEATURE_BACKLOG.md) / Decisions). |
| **Точки отказа** | Бот не отвечает (polling/down); заблокирован ранее; Telegram не доставляет. |
| **Как улучшить** | Стабильный хостинг + supervise ([RL-01](FEATURE_BACKLOG.md) есть, [WA-02](FEATURE_BACKLOG.md) / [RL-03](FEATURE_BACKLOG.md)); админ-алерт при падении. |
| **Приоритет улучшения** | **P0** (без ответа бота journey мёртв) |

## Шаг 2. Получает первое сообщение

| Поле | Содержание |
|------|------------|
| **Цель пользователя** | Понять, что делать дальше за &lt;30 секунд. |
| **Что видит** | 1) Приветствие `welcome_text()`: бренд, «маршрут + макс. цена», алерт при ≤ порога, список умений, шаги 1–3. 2) Reply-меню: `🛩 Открыть приложение` (если задан `WEBAPP_URL`), `➕ Добавить`, `📋 Мои маршруты`, `🔄 Проверить цены`, `ℹ️ Помощь`. 3) Если есть `WEBAPP_URL` — второе сообщение про Mini App + inline «открыть». 4) «Быстрый старт» — популярные направления (MOW→AYT/IST/DXB/SSH, LED→AYT). |
| **Действия** | Читает; выбирает «Добавить», популярный маршрут или Mini App. |
| **Где может запутаться** | Три сообщения подряд — перегруз; не отличить «вилка рынка» от «порог»; Mini App кнопка vs «Добавить»; не сказано явно «сейчас всегда 1 взрослый». |
| **Точки отказа** | Битый `WEBAPP_URL` (Error 1033 / не открывается) → разочарование в бренде; игнор текста → уход; demo-цены на проде → недоверие позже. |
| **Как улучшить** | Сжать /start под USP watchdog ([TG-02](FEATURE_BACKLOG.md)); не показывать битую кнопку Mini App ([WA-03](FEATURE_BACKLOG.md)); одна CTA «Добавить» выше сгиба; честный дисклеймер pax в welcome. |
| **Приоритет улучшения** | **P0–P1** (копирайт P1; битый Mini App / demo — P0) |

## Шаг 3. Создаёт первое отслеживание

| Поле | Содержание |
|------|------------|
| **Цель пользователя** | Заставить бота сторожить конкретную поездку по приемлемой цене. |
| **Что видит / делает (бот FSM)** | `➕ Добавить` или quick-route → **Откуда** (город/код) → при неоднозначности — picker → **Куда** → **Дата** или «Любая дата» → **Тип** one-way / round → при RT дата возврата (или +7 дней) → **гибкость дат** (только эта / ±1 / ±3 / ±7) → превью с ценой и **вилкой** → кнопки порога «дёшево / обычно / своя» (+ CS-05 warn) → подтверждение, карточка подписки, кнопки действий + «Смотреть билеты». Альтернатива: Mini App (Поиск → вилка → гибкость → «Следить»). Пассажиров UI **не спрашивает** (всегда 1 взр.). |
| **Действия** | Вводит города, даты, выбирает порог; либо тапает популярный маршрут. |
| **Где может запутаться** | Формат даты; несколько аэропортов в picker; RT ≈ сумма двух OW (дисклеймер есть, но легко пропустить); порог «дёшево» vs своя сумма; ожидание цены «за семью»; путаница рынок vs порог на карточке. |
| **Точки отказа** | Город не нашёлся; API/demo ошибка вилки → просят ввести число вручную; бросил FSM (нет прогресса); поставил порог ≪ P25 → подписка «мёртвая»; отменил и не вернулся. |
| **Как улучшить** | Предупреждение порога ниже рынка ([CS-05](FEATURE_BACKLOG.md)); явный timestamp на карточке ([TR-04](FEATURE_BACKLOG.md)); упростить RT-дисклеймер; прогресс «шаг 2/4»; после создания — ожидание «напишу, когда ≤ Y». |
| **Приоритет улучшения** | **P0** (CS-05, ясность порога — критично для North Star) |

## Шаг 4. Получает первое уведомление

| Поле | Содержание |
|------|------------|
| **Цель пользователя** | Узнать, что пора смотреть билеты, не проверяя цены самому. |
| **Что видит** | Push/сообщение в чате от бота: карточка маршрута (formatters), текущая цена, вилка/порог (если переданы в шаблон), статус «ниже порога», inline **🎫 Смотреть билеты** + действия watch. Срабатывание: фоновый `PriceChecker`, условие `quote.price <= max_price`. Интервал — из `CHECK_INTERVAL_*` (часто десятки минут). |
| **Действия** | Открывает чат; читает; тапает «Смотреть билеты» или игнорирует / удаляет подписку. |
| **Где может запутаться** | Не помнит, какой ставил порог; не понимает, «насколько это дёшево»; повторные алерты на ту же цену (антиспам **не** использует `last_alert_price` для глушения); нет явного «проверили в HH:MM». |
| **Точки отказа** | Порог недостижим → **алерта никогда не будет** (тихий churn); бот/checker down; Telegram block; спам → Block; цена уже выросла к моменту открытия (ожидаемо на рынке). |
| **Как улучшить** | Антиповтор ([NT-04](FEATURE_BACKLOG.md)); жёсткий контракт X≤Y в тексте ([NT-02](FEATURE_BACKLOG.md)); вилка в алерте ([NT-03](FEATURE_BACKLOG.md)); timestamp ([TR-04](FEATURE_BACKLOG.md)); лог алертов ([AN-03](FEATURE_BACKLOG.md)). |
| **Приоритет улучшения** | **P0** |

## Шаг 5. Переходит по партнёрской ссылке

| Поле | Содержание |
|------|------------|
| **Цель пользователя** | Увидеть актуальные билеты и (часто) купить. |
| **Что видит** | Уход в браузер/Aviasales: `aviasales.ru/search?...&marker=...` (`build_affiliate_url`). Дальше — UI Aviasales, не FlyPing. |
| **Действия** | Сравнивает рейсы; покупает / сохраняет / закрывает. |
| **Где может запутаться** | Цена на Aviasales ≠ цифра в алерте (кэш/состав/момент); не понимает, что FlyPing не продаёт билет; возврат в бота неочевиден. |
| **Точки отказа** | Битая/устаревшая ссылка; пользователь не завершает покупку; **мы не видим клик/бронь** в продукте (нет AN-01). |
| **Как улучшить** | Трекинг alert→click ([AN-01](FEATURE_BACKLOG.md)); в алерте дисклеймер «цена ориентир, на сайте может отличаться»; кнопка «Вернуться к подписке» после возврата в чат (гипотеза UX); sub-marker по источнику ([GR-01](FEATURE_BACKLOG.md)). |
| **Приоритет улучшения** | **P1** (монетизация и честность; не блокирует первый алерт, но блокирует обучение продукта) |

## Шаг 6. Возвращается и создаёт второе отслеживание

| Поле | Содержание |
|------|------------|
| **Цель пользователя** | Сторожить ещё один маршрут / другие даты; закрепить привычку. |
| **Что видит** | Снова меню бота; `📋 Мои маршруты` со списком карточек; `➕ Добавить` или Mini App «Подписки» / «Поиск». Лимита маршрутов сейчас **нет** (FREE_WATCH_LIMIT не enforced). |
| **Действия** | Добавляет второй watch тем же FSM/Mini App; опционально `/check`, удаление старого. |
| **Где может запутаться** | Не находит, как изменить порог у первого (редактирования нет — только удалить); путает две подписки; не шарит успех друзьям (нет share). |
| **Точки отказа** | Первый опыт был шумом/тишиной → не возвращается; Mini App снова мёртв; нет причины звать друга (нет deep-link/share). |
| **Как улучшить** | Edit порога ([TR-05](FEATURE_BACKLOG.md)); шаринг карточки ([TG-04](FEATURE_BACKLOG.md)); deep-link ([TG-03](FEATURE_BACKLOG.md)); после первого алерта — soft-prompt «Добавить ещё направление?»; позже — осознанный freemium ([TR-06](FEATURE_BACKLOG.md)/[PR-01](FEATURE_BACKLOG.md)). |
| **Приоритет улучшения** | **P1** (retention и рост; после P0 алертов) |

## Сводка точек отказа (воронка)

```text
Нашёл ссылку
    │  отказ: не Start / ушёл к Aviasales bot
    ▼
/start и меню
    │  отказ: бот молчит / битый Mini App
    ▼
Создал watch
    │  отказ: бросил FSM / город не найден / порог «в космос»
    ▼
Ждёт…
    │  отказ: никогда не алерт (порог) / простой checker
    ▼
Алерт
    │  отказ: спам → Block / игнор
    ▼
Клик на Aviasales
    │  отказ: цена другая / не купил  (для NSM клик не обязателен, для CPA — да)
    ▼
Второе отслеживание
       отказ: не вернулся / нельзя удобно править первую
```

**Связь с North Star (Alerted Watchers 30d):** шаги 3→4 обязательны; шаг 0–2 определяют, дойдёт ли человек до watch; шаг 5 — коммерция; шаг 6 — retention и вирусность.

## Чего в journey намеренно нет
