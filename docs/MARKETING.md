## Позиционирование для внешних коммуникаций

> FlyPing — сторож цены на авиабилеты.

Механика в одном абзаце: направление → даты → максимальная цена → регулярная проверка → уведомление в Telegram → покупка у партнёра.

Не позиционировать как авиакомпанию, турагентство, кассу, полный каталог или «гарантию самой низкой цены». Детали обещаний: [BLOGGER_KIT](BLOGGER_KIT.md) §§8–9, [COPY_GUIDE](COPY_GUIDE.md).

## Что уже можно использовать для коммуникаций (факт продукта)

- Fixed copy TG-02: «сторож цены», не каталог рейсов  
- Блогер-кит GR-02: 3 креатива, короткие форматы, сторис, FAQ, checklist  
- Attribution-ссылки `?start=<payload>` (латиница, 1–64)  
- Вилка: дёшево / обычно / дорого (в продукте)  
- Алерт: цена не выше порога + переход к партнёру  

Популярные маршруты на `/start` (намёк на спрос, не аналитика):

- MOW → AYT, IST, DXB, SSH  
- LED → AYT

## Ограничения, которые влияют на маркетинг

1. Без стабильного HTTPS Mini App «отваливается» для пользователей Telegram.  
2. Выбор пассажиров скрыт — нельзя честно рекламировать «цену за семью», пока нет Flight Search.  
3. Round-trip без live ≈ сумма one-way — нельзя обещать «точную цену RT» в креативах.  
4. CPA-выручка зависит от клика по партнёру — креатив ведёт к «следить → алерт → открыть билеты».  
5. Referral rewards не обещать — их ещё нет в продукте.

## Минимальный go-to-market для текущего MVP

1. Стабильный бот + `WEBAPP_URL`  
2. Материалы из [BLOGGER_KIT.md](BLOGGER_KIT.md) + уникальный payload на размещение  
3. Закрытая группа / первые каналы без выдуманных гарантий экономии  
4. Смотрим: `/start` с attribution, созданные подписки, алерты  
5. Смотрим в кабинете партнёра: клики/брони по маркеру  
6. Учёт размещений — ручная таблица в блогер-ките (не dashboard)
