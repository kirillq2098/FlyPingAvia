# FlyPingAvia

Telegram-бот для мониторинга цен на авиабилеты.

Пользователь задаёт маршрут и порог цены — бот следит за предложениями и присылает алерт, когда билет стал дешевле. Деньги появляются не от самих уведомлений, а от **конверсии в покупку** и **платного удобства**.

## Зачем это нужно

Агрегаторы показывают текущую цену. FlyPingAvia решает другую задачу: **не пропустить момент**, когда цена упала до приемлемого уровня — без ручного открытия сайтов каждый день.

Типичные сценарии:

- гибкие выходные / отпуск без жёстких дат;
- регулярные маршруты (дом ↔ другой город);
- «улететь на неделю», когда появится выгодный вариант.

## Ценностное предложение

| Для кого | Что получает |
|----------|--------------|
| Путешественник | Точные алерты в Telegram, без спама |
| Платный подписчик | Больше маршрутов, гибкие фильтры, приоритет |
| Турагентство / travel-менеджер | Каналы, отчёты, API (этап B2B) |

## Монетизация

### 1. Affiliate / CPA (старт)

Партнёрки агрегаторов и авиакомпаний (Aviasales / Travelpayouts, Kiwi и др.): ссылка с меткой → комиссия с бронирования.

Масштаб = больше маршрутов × пользователей × точных алертов → больше кликов и покупок.

### 2. Freemium-подписка

| | Бесплатно | Платно (ориентир 99–299 ₽/мес) |
|--|-----------|--------------------------------|
| Маршруты | 1–2 | больше лимитов |
| Проверки | реже | чаще / приоритетные |
| Фильтры | базовые | даты ±N, багаж, пересадки |
| Дополнительно | — | история цен, дайджест, семейный план |

Подписку включать после того, как бесплатные алерты уже дают ощутимую ценность.

### 3. B2B / white-label

Турагентствам и корпоративным travel-менеджерам: API, Telegram/Slack-каналы, отчёты по бюджету. Чек выше, чем у B2C — следующий слой после стабильного B2C.

### 4. Доп. услуги (позже)

Страховки, отели, трансфер, динамические пакеты — только после устойчивого трафика на билеты.

## Масштабирование

| Слой | Что делать |
|------|------------|
| Данные | Несколько источников цен, кэш, умный polling (чаще на «горячих» маршрутах) |
| Продукт | Календарь дешевизны, гибкие даты, подписка на город/страну, групповые поездки |
| Каналы | SEO-минисайт + бот, вирусный шаринг алертов, travel-блогеры |
| Удержание | Полезные алерты без спама; персональные пороги и «тихие часы» |
| Юнит-экономика | CAC, LTV, воронка alert → клик → покупка по источникам |

## Roadmap

1. **MVP** — бот + 1–2 партнёрки + популярные направления (например, Москва ↔ Стамбул / Сочи / Дубай).
2. **Юнит-экономика** — 100–1000 активных подписчиков; измерить конверсию в клик и бронь.
3. **Подписка** — лимиты, точность, приоритет после доказанной ценности free-тира.
4. **Автоматизация данных и антиспам** — без этого рост убивает доверие.
5. **B2B / API** — когда есть стабильный пайплайн цен и понятный SLA.

## Дифференциация и риски

**Отстройка:** скорость и точность алертов в Telegram + узкие сценарии (выходные, регулярные маршруты, «улететь на неделю»), а не «ещё один поиск билетов».

**Риски:** зависимость от API/агрегаторов, смена правил партнёрок, ложные алерты, конкуренция с Aviasales / Google Flights.

## Стек (целевой)

Репозиторий на старте пустой — стек будет зафиксирован по мере реализации MVP. Ориентир:

- **Бот:** Python + aiogram / python-telegram-bot
- **Очереди и планировщик:** Redis + Celery / ARQ (проверки цен)
- **Хранение:** PostgreSQL (пользователи, подписки, история цен)
- **Источники цен:** партнёрские API агрегаторов
- **Деплой:** Docker, простой VPS или PaaS

## Метрики успеха

- MAU / DAU бота и число активных подписок на маршруты
- Конверсия alert → клик → бронирование
- Revenue: affiliate + подписки
- Качество: доля ложных/бесполезных алертов, churn подписки

## Статус

Проект в начале: описание продукта и стратегия монетизации зафиксированы. Код MVP — следующий шаг.
